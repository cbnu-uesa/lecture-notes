MCP Model Context Protocol

AI에 바깥 도구를 꽂는 규격.
한 번 꽂아 두면 "그 데이터 받아 줘" 로 끝난다

→ 파일을 사람이 나르는 대신, 클로드가 직접 가서 가져온다.
   공공데이터 API·데이터베이스·사내 문서가 모두 같은 방식으로 붙는다

붙이면 무엇이 달라지나

받아 놓고 끝이 아니다 — 루프

큰 일은 나눠 맡긴다 — 서브에이전트

한 대화가 다 하려 하면 앞의 내용이 밀려나고 헷갈린다

맡기는 일왜 나누나
구별로 데이터 받기넷을 동시에 시켜도 서로 방해하지 않는다
받은 것 검증하기받은 사람과 검사하는 사람을 나누면 놓치는 게 준다
결과 요약하기중간 과정을 다 기억할 필요가 없다

사람 조직과 같다. 나눠서 시키고, 올라온 것을 합친다.

언제 쓰지 않을 것인가

한 번 받고 끝날 데이터에 도구를 붙이고
루프를 만들면 손해다

→ 기준은 하나다. 반복하는가.
   세 번 넘게 할 일이면 자동화가 이기고, 아니면 그냥 시키는 게 빠르다

실습

받는 일과 검증하는 일을 넘기기 — 약 1시간 30분

실습 ① — API 를 붙인다 30분

  1. 3주차 인증키를 꺼낸다. CLAUDE.md 에 적지 않는다 — 비밀은 별도 파일에 두고 그 파일은 공유하지 않는다
  2. 클로드에게 맡긴다 — 매번 손으로 내려받는 대신 직접 불러오게 한다

프롬프트

"3주차에 쓴 실거래가 API 를 이제 네가 직접 부르게 하고 싶어. 인증키는 .env 에 넣어 둘게.

먼저 어떻게 붙일 생각인지 알려 주고, 확인하면 진행해. 붙인 다음에는 서원구 최근 3개월을 받아 봐."

서원구 코드는 3주차에 직접 찾아 둔 것을 쓴다.

실습 ② — 무엇을 검증할지 정한다 20분

"제대로 받았다" 를 무엇으로 판정할 것인가. 사람이 정한다

검증 항목어긋나면 무슨 일인가
기간이 다 찼나한 달이 통째로 비면 그 달만 요청이 실패한 것이다
건수가 그럴듯한가0건이나 갑자기 10배면 지역코드나 기간이 잘못됐다
필수 열이 다 있나API 응답 형식이 바뀌면 조용히 열이 빠진다
결측·중복같은 거래가 두 번 들어오면 평균이 흔들린다
값의 범위가격이 음수거나 면적이 0 이면 받는 중에 깨진 것이다

이 표를 CLAUDE.md 에 옮겨 적는다. 다음부터는 말하지 않아도 검사한다.

실습 ③ — 루프를 돌린다 25분

프롬프트

"이제 받고 → 검증하고 → 문제가 있으면 고치고 → 다시 검증하는 순서로 해 줘. 검증 항목은 CLAUDE.md 에 적어 뒀어.

통과할 때까지 스스로 반복하되, 세 번 해도 안 되면 멈추고 나에게 물어봐.

끝나면 무엇을 검사했고 무엇이 걸렸는지 기록으로 남겨 줘."

"세 번 해도 안 되면 멈춰라" 를 반드시 넣는다. 없으면 같은 실패를 끝없이 반복할 수 있다.

일부러 틀려 본다

존재하지 않는 기간(예: 2099년 1월)이나 잘못된 지역코드를 넣어 시킨다. 루프가 실제로 잡아내는지 본다. 잡지 못하면 검증 항목이 부족한 것이다.

실습 ④ — 쓰지 않을 자리를 적는다 15분

오늘 만든 것을 되돌아보고 세 줄로 답한다

  1. 이 루프를 만드는 데 든 시간과, 손으로 했을 때의 시간을 견줘 본다
  2. 몇 번부터 이득인가 — 내 프로젝트 기준으로 답해 본다
  3. 자동화하지 않는 편이 나은 작업을 하나 적는다

제출: 수집·검증 루프 기록 (일부러 넣은 오류를 잡아낸 화면 포함)

가정 과제: 자기 프로젝트 데이터에도 검증 항목을 정해 CLAUDE.md 에 적어 둔다. 다음 주는 중간고사가 아니라 기술적 분석이다 — 여기까지가 도구 편이다.
