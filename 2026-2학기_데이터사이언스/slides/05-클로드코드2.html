5강. 클로드 코드 Ⅱ
스킬 · 플러그인 · MCP · 에이전트

 

CLAUDE.md 가 마흔 줄이 되면?

  • 지난주에 규칙을 적어 재현되게 만들었다
  • 그런데 "월별 요약 만드는 절차" 까지 거기 적으면 길어진다
  • 데이터를 매번 손으로 내려받는 일도 남아 있다

클로드 코드를 넓히는 네 가지

무엇넓혀 주는 것한 줄로
① 스킬정해진 절차"이 작업은 이 순서로"
② 플러그인스킬·에이전트 등을 묶어 배포"남과 나눠 쓴다"
③ MCP바깥 도구와 데이터"직접 가서 가져온다"
④ 에이전트일을 나눠 맡기기"따로 시키고 결과만 받는다"

CLAUDE.md 가 "항상 이렇게" 라면, 오늘 배우는 넷은 "필요할 때 이것을" 이다.

① 스킬

절차를 파일 하나로 묶는다

같은 지시를 반복해서 붙여 넣고 있다면 그것은 스킬이 될 자리다.

폴더 하나에 SKILL.md 를 두면 된다. 폴더 이름이 곧 명령 이름이 된다.

앞머리의 description 이 중요하다 — 클로드가 언제 이 스킬을 꺼낼지 그 문장으로 판단한다.

본문은 쓸 때만 읽힌다. 그래서 길어도 평소에 비용이 들지 않는다 — CLAUDE.md 와 결정적으로 다른 점이다.

.claude/skills/월별요약/SKILL.md
---
description: 월별 실거래 요약표를 만든다.
  달을 지정하면 건수·중앙값·최고·최저 동을
  표로 낸다.
---

지정한 달($ARGUMENTS)의 거래를 골라
CLAUDE.md 의 분석 규칙을 그대로 적용한다.

1. 해당 월 계약분만 추린다
2. 전용면적 하한을 적용한다
3. 동별 ㎡당 가격의 중앙값을 낸다
4. 표로 정리하고 뺀 동을 아래에 적는다

/월별요약 202608 로 부른다

① 스킬

어디에 두느냐로 범위가 갈린다

위치범위부르는 이름
~/.claude/skills/<이름>/SKILL.md내 모든 프로젝트 /이름
.claude/skills/<이름>/SKILL.md이 프로젝트 /이름
<플러그인>/skills/<이름>/SKILL.md플러그인이 켜진 곳 /플러그인:이름

스킬은 두 가지 방식으로 불린다 — 내가 /이름 으로 직접 부르거나, 클로드가 description 을 보고 알아서 꺼내 쓴다.

스킬 파일을 고치면 세션 중에도 반영된다. 새 스킬 폴더를 처음 만들 때만 재시작이 필요할 수 있다.

① 스킬

CLAUDE.md 와 스킬을 가르는 기준

CLAUDE.md스킬
담는 것사실과 규범절차
언제 읽히나그 폴더의 모든 대화그 작업을 부를 때만
길어지면매번 비용이 든다비용이 들지 않는다
예"면적 하한은 60㎡""월별 요약을 이 순서로"

CLAUDE.md 의 한 절이 절차로 자라났다면 스킬로 옮길 때다. 세 번 넘게 할 일에만 만든다 — 규격화에도 품이 든다.

② 플러그인

묶어서 나눠 쓴다

스킬·에이전트·훅·MCP 설정을 한 폴더에 묶은 것이 플러그인이다.

혼자 쓸 때는 .claude/ 로 충분하다. 남과 나눠 쓰거나 버전을 붙이려 할 때 플러그인으로 만든다.

설치하기

터미널 · 클로드 코드 안
/plugin          마켓플레이스에서 찾아 설치
/reload-plugins  설치 뒤 반영이 필요하면

4강에서 쓴 claude-md-management 가 그 예다.

만들기 — 폴더 구조

my-plugin/
.claude-plugin/plugin.json   이름·설명·버전
skills/      <이름>/SKILL.md
agents/      에이전트 정의
hooks/       hooks.json
.mcp.json    MCP 서버 설정

주의 — .claude-plugin/ 안에는 plugin.json 만 넣는다. 나머지는 전부 플러그인 루트에 둔다.

시험해 보기
claude --plugin-dir ./my-plugin

③ MCP

바깥 도구를 꽂는 규격

③ MCP

붙이는 법과 범위

터미널
# 원격 서버 (주소가 있는 경우)
claude mcp add --transport http \
  <이름> <주소>

# 내 컴퓨터에서 실행하는 서버
claude mcp add <이름> -- <실행 명령>

# 붙은 서버 확인
/mcp

-- 뒤는 서버를 실행하는 명령이다. 그대로 전달된다.

범위를 정한다 — --scope

범위어디까지
local
기본값		 나 · 이 프로젝트에서만
project .mcp.json 에 적혀 저장소에 함께 간다
user내 모든 프로젝트

인증키는 .mcp.json 에 적지 않는다. 그 파일은 저장소에 올라간다 — 환경변수로 넘긴다.

③ MCP

주의 — 붙였다고 믿지 않는다

조심할 것왜
아무 서버나 붙이지 않는다MCP 서버는 내 자료를 읽고 바깥으로 보낼 수 있다. 누가 만들었는지 모르면 붙이지 않는다
받은 것을 검사한다손으로 받을 때는 눈으로 봤다. 자동이 되면 이상해도 그대로 지나간다
도구가 늘면 느려진다쓰지 않는 서버는 꺼 둔다
바깥이 바뀐다API 응답 형식이 바뀌면 조용히 열이 빠진다

두 번째가 이 수업의 자리다 — 무엇을 검증할지는 사람이 정한다.

④ 에이전트

따로 시키고 결과만 받는다

서브에이전트는 자기 대화창을 따로 가진 클로드다. 시킨 일을 그 안에서 하고 요약만 돌려준다.

쓰는 이유 셋

  • 본 대화가 깨끗해진다 — 로그·검색 결과가 넘어오지 않는다
  • 권한을 좁힐 수 있다 — 검사역에게는 읽기만 준다
  • 여럿을 동시에 시킬 수 있다

.claude/agents/ 에 두면 이 프로젝트, ~/.claude/agents/ 에 두면 모든 프로젝트에서 쓴다.

.claude/agents/data-checker.md
---
name: data-checker
description: 받은 데이터가 제대로 왔는지
  검사한다. 기간·행 수·결측·이상치를 본다.
tools: Read, Grep, Bash
model: sonnet
---

너는 데이터 검사역이다. 고치지 말고
무엇이 잘못됐는지만 보고한다.

1. 요청한 기간이 다 찼는지
2. 행 수가 그럴듯한지
3. 결측·중복·음수 가격이 없는지
4. 필수 열이 다 있는지

tools 로 쓸 수 있는 도구를 제한한다. 검사역에게 쓰기 권한을 주지 않는 것이 요점이다.

④ 에이전트

받고 · 검증하고 · 고치는 루프

언제 쓰지 않을 것인가

한 번 하고 말 일에 스킬을 만들고 MCP 를 붙이고
루프를 짜면 손해다

→ 기준은 하나다. 반복하는가.
   세 번 넘게 할 일이면 규격화가 이기고, 아니면 그냥 시키는 게 빠르다

실습

스킬 만들고 · 도구 붙이고 · 검사역 두기 — 약 1시간 30분

오늘 실습의 도착점

지난주 폴더에 스킬 하나와 검사역 하나를 붙인다

시각할 일끝났다는 신호
0:00–0:30① 스킬 만들기부르지 않아도 클로드가 꺼내 쓴다
0:30–1:05② 검사역 에이전트와 루프일부러 넣은 오류를 잡아낸다
1:05–1:30③ 도구 붙이기손으로 안 받고 가져온다

순서를 강의와 바꿨다. ③은 환경에 따라 오래 걸릴 수 있어 뒤로 뺐다 — ①②가 오늘의 필수이고 ③은 되는 데까지 한다.

시작 전 확인

지난주 ds2026/ 폴더와 그 안의 CLAUDE.md · 3주차 인증키

① 스킬을 만든다 0:00–0:30

  1. CLAUDE.md 를 다시 읽고 절차에 해당하는 부분을 찾는다 — "무엇을 계산한다" 가 아니라 "어떤 순서로 한다" 인 것 5분
  2. 폴더와 파일을 만든다
    mkdir -p .claude/skills/월별요약 → 그 안에 SKILL.md 10분
  3. /월별요약 202608 로 불러 본다 5분
  4. 이번에는 부르지 말고 "8월 실거래 요약 좀" 이라고만 한다 10분
✓ 확인 지점 — 4번에서 클로드가 스스로 스킬을 꺼내 쓴다. 안 되면 description 이 부족한 것이다 — "언제 쓰는 스킬인지" 를 더 구체적으로 고쳐 다시 한다.
무엇을 스킬로 할지 모르겠으면 — "월별 실거래 요약" 을 그대로 쓴다. 지정한 달의 건수·중앙값·최고/최저 동을 표로 내는 절차다. 자기 것이 생기면 나중에 바꾸면 된다.

② 무엇을 검사할지 먼저 정한다 0:30–0:45

"제대로 받았다" 를 무엇으로 판정할 것인가. 사람이 정한다

검사 항목어긋나면 무슨 일인가
기간이 다 찼나한 달이 통째로 비면 그 달 요청만 실패한 것이다
건수가 그럴듯한가0건이거나 갑자기 10배면 지역코드나 기간이 잘못됐다
필수 열이 다 있나응답 형식이 바뀌면 조용히 열이 빠진다
결측·중복같은 거래가 두 번 들어오면 평균이 흔들린다
값의 범위가격이 음수거나 면적이 0 이면 받는 중에 깨진 것이다
✓ 확인 지점 — 이 표를 CLAUDE.md 에 옮겨 적었다. 다음부터는 말하지 않아도 검사한다.

항목을 더해도 좋다. 다만 "이상하면 알려 줘" 같은 말은 항목이 아니다 — 무엇을 보고 판정하는지 적어야 검사가 된다.

② 검사역을 두고 루프를 돌린다 0:45–1:05

  1. .claude/agents/data-checker.md 를 만든다. tools 에 쓰기 도구를 넣지 않는다 — 검사역은 고치지 않는다 8분
  2. 루프를 시킨다 7분

그대로 쓴다

"데이터를 받고 → data-checker 에게 넘겨 검사하고 → 문제가 있으면 고치고 → 다시 검사하는 순서로 해 줘. 검사 항목은 CLAUDE.md 에 있어.

통과할 때까지 반복하되, 세 번 해도 안 되면 멈추고 나에게 물어봐. 끝나면 무엇을 검사했고 무엇이 걸렸는지 기록으로 남겨 줘."

  1. 일부러 틀린다 — 없는 기간(2099년 1월)이나 잘못된 지역코드를 넣고 다시 돌린다 5분
✓ 확인 지점 — 루프가 일부러 넣은 오류를 잡아낸다. 못 잡으면 검사 항목이 부족한 것이다. 이 화면을 남긴다.

③ 도구를 붙인다 1:05–1:30

두 갈래 중 하나를 고른다. 둘 다 "손으로 안 받는다" 는 같은 목적이다

갈래난이도이렇게 한다
A. 스킬로 감싸기쉽다 · 대부분 성공 API 호출 스크립트를 만들고 그것을 부르는 스킬을 둔다
B. MCP 서버환경을 탄다 claude mcp add 로 붙이고 /mcp 로 확인

프롬프트

"실거래가 API 를 네가 직접 부르게 하고 싶어. A(스크립트+스킬)와 B(MCP 서버) 중 내 환경에 뭐가 나은지 먼저 말해 주고, 어떻게 붙일지 알려 줘. 확인하면 진행해. 인증키는 환경변수로 줄게."

✓ 확인 지점 — 서원구 최근 3개월을 손으로 받지 않고 가져온다. 받은 뒤 ②의 검사역이 자동으로 도는지도 본다.
안 되면 그대로 둔다. 어디까지 갔고 무엇에 막혔는지만 적어 제출한다 — 막힌 지점을 아는 것도 결과다. 인증키는 어느 파일에도 적지 않았는지 마지막으로 확인한다.

제출물

무엇필수어느 정도면 되나
SKILL.md필수 부르지 않아도 꺼내진 화면을 함께
data-checker.md필수 tools 에 쓰기 도구가 없어야 한다
루프 실행 기록필수 일부러 넣은 오류를 잡아낸 화면
도구 연결 기록되는 데까지 막혔으면 어디서 왜 막혔는지

세 번째가 오늘의 핵심 증거다. 검증은 사람이 정하고 AI 가 수행한다 를 화면으로 보여 주는 것이다.

가정 과제 — 만든 것 중 남과 나눠 쓸 만한 것이 있으면 플러그인 구조로 묶어 본다 (.claude-plugin/plugin.json + skills/ + agents/). 다음 주에 이 폴더를 저장소로 만든다.
