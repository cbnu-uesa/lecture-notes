5강. 클로드 코드 Ⅱ
스킬 · 플러그인 · MCP · 에이전트

 

CLAUDE.md 가 마흔 줄이 되면?

  • 지난주에 규칙을 적어 재현되게 만들었다
  • 그런데 "월별 요약 만드는 절차" 까지 거기 적으면 길어진다
  • 데이터를 매번 손으로 내려받는 일도 남아 있다

클로드 코드를 넓히는 네 가지

무엇넓혀 주는 것한 줄로
① 스킬정해진 절차"이 작업은 이 순서로"
② 플러그인스킬·에이전트 등을 묶어 배포"남과 나눠 쓴다"
③ MCP바깥 도구와 데이터"직접 가서 가져온다"
④ 에이전트일을 나눠 맡기기"따로 시키고 결과만 받는다"

CLAUDE.md 가 "항상 이렇게" 라면, 오늘 배우는 넷은 "필요할 때 이것을" 이다.

① 스킬

절차를 파일 하나로 묶는다

같은 지시를 반복해서 붙여 넣고 있다면 그것은 스킬이 될 자리다.

폴더 하나에 SKILL.md 를 두면 된다. 폴더 이름이 곧 명령 이름이 된다.

앞머리의 description 이 중요하다 — 클로드가 언제 이 스킬을 꺼낼지 그 문장으로 판단한다.

본문은 쓸 때만 읽힌다. 그래서 길어도 평소에 비용이 들지 않는다 — CLAUDE.md 와 결정적으로 다른 점이다.

.claude/skills/월별요약/SKILL.md
---
description: 월별 실거래 요약표를 만든다.
  달을 지정하면 건수·중앙값·최고·최저 동을
  표로 낸다.
---

지정한 달($ARGUMENTS)의 거래를 골라
CLAUDE.md 의 분석 규칙을 그대로 적용한다.

1. 해당 월 계약분만 추린다
2. 전용면적 하한을 적용한다
3. 동별 ㎡당 가격의 중앙값을 낸다
4. 표로 정리하고 뺀 동을 아래에 적는다

/월별요약 202608 로 부른다

① 스킬

어디에 두느냐로 범위가 갈린다

위치범위부르는 이름
~/.claude/skills/<이름>/SKILL.md내 모든 프로젝트 /이름
.claude/skills/<이름>/SKILL.md이 프로젝트 /이름
<플러그인>/skills/<이름>/SKILL.md플러그인이 켜진 곳 /플러그인:이름

스킬은 두 가지 방식으로 불린다 — 내가 /이름 으로 직접 부르거나, 클로드가 description 을 보고 알아서 꺼내 쓴다.

스킬 파일을 고치면 세션 중에도 반영된다. 새 스킬 폴더를 처음 만들 때만 재시작이 필요할 수 있다.

① 스킬

CLAUDE.md 와 스킬을 가르는 기준

CLAUDE.md스킬
담는 것사실과 규범절차
언제 읽히나그 폴더의 모든 대화그 작업을 부를 때만
길어지면매번 비용이 든다비용이 들지 않는다
예"면적 하한은 60㎡""월별 요약을 이 순서로"

CLAUDE.md 의 한 절이 절차로 자라났다면 스킬로 옮길 때다. 세 번 넘게 할 일에만 만든다 — 규격화에도 품이 든다.

② 플러그인

묶어서 나눠 쓴다

스킬·에이전트·훅·MCP 설정을 한 폴더에 묶은 것이 플러그인이다.

혼자 쓸 때는 .claude/ 로 충분하다. 남과 나눠 쓰거나 버전을 붙이려 할 때 플러그인으로 만든다.

설치하기

터미널 · 클로드 코드 안
/plugin          마켓플레이스에서 찾아 설치
/reload-plugins  설치 뒤 반영이 필요하면

4강에서 쓴 claude-md-management 가 그 예다.

만들기 — 폴더 구조

my-plugin/
.claude-plugin/plugin.json   이름·설명·버전
skills/      <이름>/SKILL.md
agents/      에이전트 정의
hooks/       hooks.json
.mcp.json    MCP 서버 설정

주의 — .claude-plugin/ 안에는 plugin.json 만 넣는다. 나머지는 전부 플러그인 루트에 둔다.

시험해 보기
claude --plugin-dir ./my-plugin

③ MCP

바깥 도구를 꽂는 규격

③ MCP

붙이는 법과 범위

터미널
# 원격 서버 (주소가 있는 경우)
claude mcp add --transport http \
  <이름> <주소>

# 내 컴퓨터에서 실행하는 서버
claude mcp add <이름> -- <실행 명령>

# 붙은 서버 확인
/mcp

-- 뒤는 서버를 실행하는 명령이다. 그대로 전달된다.

범위를 정한다 — --scope

범위어디까지
local
기본값		 나 · 이 프로젝트에서만
project .mcp.json 에 적혀 저장소에 함께 간다
user내 모든 프로젝트

인증키는 .mcp.json 에 적지 않는다. 그 파일은 저장소에 올라간다 — 환경변수로 넘긴다.

③ MCP

주의 — 붙였다고 믿지 않는다

조심할 것왜
아무 서버나 붙이지 않는다MCP 서버는 내 자료를 읽고 바깥으로 보낼 수 있다. 누가 만들었는지 모르면 붙이지 않는다
받은 것을 검사한다손으로 받을 때는 눈으로 봤다. 자동이 되면 이상해도 그대로 지나간다
도구가 늘면 느려진다쓰지 않는 서버는 꺼 둔다
바깥이 바뀐다API 응답 형식이 바뀌면 조용히 열이 빠진다

두 번째가 이 수업의 자리다 — 무엇을 검증할지는 사람이 정한다.

④ 에이전트

따로 시키고 결과만 받는다

서브에이전트는 자기 대화창을 따로 가진 클로드다. 시킨 일을 그 안에서 하고 요약만 돌려준다.

쓰는 이유 셋

  • 본 대화가 깨끗해진다 — 로그·검색 결과가 넘어오지 않는다
  • 권한을 좁힐 수 있다 — 검사역에게는 읽기만 준다
  • 여럿을 동시에 시킬 수 있다

.claude/agents/ 에 두면 이 프로젝트, ~/.claude/agents/ 에 두면 모든 프로젝트에서 쓴다.

.claude/agents/data-checker.md
---
name: data-checker
description: 받은 데이터가 제대로 왔는지
  검사한다. 기간·행 수·결측·이상치를 본다.
tools: Read, Grep, Bash
model: sonnet
---

너는 데이터 검사역이다. 고치지 말고
무엇이 잘못됐는지만 보고한다.

1. 요청한 기간이 다 찼는지
2. 행 수가 그럴듯한지
3. 결측·중복·음수 가격이 없는지
4. 필수 열이 다 있는지

tools 로 쓸 수 있는 도구를 제한한다. 검사역에게 쓰기 권한을 주지 않는 것이 요점이다.

④ 에이전트

받고 · 검증하고 · 고치는 루프

언제 쓰지 않을 것인가

한 번 하고 말 일에 스킬을 만들고 MCP 를 붙이고
루프를 짜면 손해다

→ 기준은 하나다. 반복하는가.
   세 번 넘게 할 일이면 규격화가 이기고, 아니면 그냥 시키는 게 빠르다

실습

스킬 만들고 · 도구 붙이고 · 검사역 두기 — 약 1시간 30분

실습 ① — 스킬을 만든다 25분

  1. 지난주 CLAUDE.md 를 다시 읽고 절차에 해당하는 부분을 찾는다
  2. .claude/skills/월별요약/SKILL.md 를 만든다. description 을 공들여 쓴다 — 클로드가 이 문장으로 판단한다
  3. /월별요약 202608 로 불러 본다
  4. 이번에는 부르지 말고 "8월 실거래 요약 좀" 이라고만 해 본다. 클로드가 스스로 스킬을 꺼내 쓰는가

4번이 안 되면 description 이 부족한 것이다. 언제 쓰는 스킬인지 더 구체적으로 고쳐 다시 해 본다.

실습 ② — 도구를 붙인다 30분

  1. 3주차 인증키를 꺼낸다. 키는 CLAUDE.md 에도 .mcp.json 에도 적지 않는다
  2. 실거래가 API 를 클로드가 직접 부르게 만든다. MCP 서버로 붙이거나, 스크립트로 감싸 스킬로 만들거나 — 둘 중 하나를 고른다
  3. /mcp 로 붙은 도구를 확인한다
  4. 서원구 최근 3개월을 받아 본다 (구 코드는 3주차에 찾아 둔 것)

프롬프트

"실거래가 API 를 네가 직접 부르게 하고 싶어. 어떻게 붙일 생각인지 먼저 알려 주고, 확인하면 진행해. 인증키는 환경변수로 줄게."

실습 ③ — 검사역을 둔다 35분

  1. 검증 항목을 사람이 먼저 정한다 — 기간이 다 찼나 · 행 수가 그럴듯한가 · 필수 열이 있나 · 결측/중복/음수가 없나
  2. .claude/agents/data-checker.md 를 만든다. tools 에 쓰기 도구를 넣지 않는다
  3. 받고 → 검사역에게 넘기고 → 문제가 있으면 고치고 → 다시 검사하는 루프를 돌린다. "세 번 해도 안 되면 멈추고 물어봐" 를 반드시 넣는다
  4. 일부러 틀려 본다 — 없는 기간(2099년 1월)이나 잘못된 지역코드. 루프가 실제로 잡는가

제출: SKILL.md + 에이전트 정의 + 루프 실행 기록 (일부러 넣은 오류를 잡아낸 화면 포함)

가정 과제: 만든 것 중 남과 나눠 쓸 만한 것이 있으면 플러그인 구조로 묶어 본다.
