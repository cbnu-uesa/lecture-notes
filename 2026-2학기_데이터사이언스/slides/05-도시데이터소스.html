조건 셋을 바꾸면 다른 지역·다른 달이 나온다. 열두 달을 받으려면 열두 번 부르면 된다 — 그것이 프로그램이 할 일이다.

법정동코드는 행정표준코드관리시스템(code.go.kr)에서 찾는다. 청주 나머지 세 구는 실습에서 직접 찾는다 — 코드를 찾는 일 자체가 오늘 배울 기술이다.

③ AI 위임은 이렇게 생겼다 — KOSIS MCP

3주차에 붙인 그 서버다

KOSIS 가 MCP 서버를 시범 운영한다. 인증키가 없고 주소 하나로 붙는다. 1,360여 종 국가승인통계, 26만여 통계표가 대상.

이렇게 묻는다

"청주시 총인구를 2020년부터 연도별로 알려 줘."

통계표 번호를 미리 알 필요가 없다. kosis_search 가 표를 찾아 주고 kosis_region_code 가 청주시 = 43110 을 돌려준다. 그 둘을 kosis_get_data 에 넣으면 숫자가 온다.

맡겼으면 확인한다

앞의 여섯 줄을 받고 바로 쓰지 않았다. 세 가지를 봤다

  1. 어느 통계표에서 왔나 — 표 이름·기관·통계표ID 를 되물었다. 대지 못하면 그 숫자는 쓰지 않는다
  2. 자릿수가 그럴듯한가 — 청주시는 85만 규모다. 처음 합산에서 167만이 나왔다. 「계」 행을 한 번 더 더한 것이었다
  3. KOSIS 화면과 같은가 — 통계표 바로가기를 열어 한 해를 대조한다
두 번째가 실제로 있었던 일이다. 받아 온 표에 「계」 행과 연령별 행이 함께 있었고, 그것을 모르고 다 더하면 인구가 두 배가 된다. 틀린 줄 몰랐다면 그대로 슬라이드에 실렸을 숫자다.

시범서비스이며 국가데이터처의 공식 입장이 아니다 — 중요한 판단 전에는 KOSIS 원자료를 확인한다 (KOSIS 공지, 2026-07-08).

받고 나서 겪는 것들

겪는 것무슨 일인가
글자가 깨진다공공기관 CSV 는 EUC-KR 인 경우가 많다. 엑셀은 열리는데 파이썬에서 깨지면 이것이다
숫자가 글자다거래금액에 쉼표가 들어 있다 — "1,250" 은 숫자가 아니다
지역이 안 맞는다행정동과 법정동은 다르다. 통계는 행정동, 부동산은 법정동인 경우가 많다
기간이 비어 있다거래가 없는 달은 행이 아예 없다. 0 이 아니라 없음이다
단위가 다르다거래금액은 만원, 면적은 ㎡. 평으로 바꾸면 어디선가 어긋난다

전부 클로드가 처리해 준다. 다만 처리했다는 사실을 알고 있어야 결과가 이상할 때 어디를 볼지 안다.

실습

청주 상당구 실거래가를 세 방식으로 받기 — 약 1시간 30분

실습 — 오늘 만들 것

대상

청주시 상당구 아파트 매매 실거래가 · 최근 12개월

원도심이 있는 구다. 4주차에 정한 연구질문과 이어지고, 6주차부터 내내 이 파일을 쓴다.

왜 세 번이나 받나

  • 같은 데이터가 나와야 내가 제대로 받았는지 알 수 있다
  • 세 방식의 손이 가는 정도를 몸으로 비교하게 된다
  • ③ 이 편하다는 것을 알되, ①②를 해 봐야 ③의 결과를 의심할 수 있다

실습 ① — 손으로 받는다 20분

  1. 국토교통부 실거래가 공개시스템 rt.molit.go.kr 에 들어간다
  2. 아파트 → 매매 → 지역을 충청북도 청주시 상당구로, 기간을 최근 12개월로 지정한다
  3. 화면에서 결과를 훑어본다 — 몇 건인가
  4. CSV 로 내려받아 열어 본다. 열 이름과 단위를 확인한다

메모해 둘 것: 전체 건수. ②③의 결과를 이것과 맞춰 본다.

조건을 하나씩 바꿔 보면 무엇이 어떻게 걸러지는지 보인다. API 의 파라미터가 곧 이 화면이다.

실습 ② — 인증키를 받는다 35분

  1. data.go.kr 회원가입 (공공데이터포털)
  2. "국토교통부_아파트 매매 실거래가 자료" 를 찾아 활용신청한다. 자동 승인이라 곧 쓸 수 있다
  3. 마이페이지에서 인증키(serviceKey)를 확인한다. 상세 화면에 요청 주소와 파라미터 설명이 함께 있다
  4. code.go.kr/stdcode/regCodeL.do 에서 법정동코드를 찾는다 — 청주시 상당구 4311100000 → 앞 5자리 43111
  5. 서원구·흥덕구·청원구의 코드도 직접 찾아 적어 둔다

인증키는 남에게 보이지 않는다. 화면 공유나 제출물에 그대로 넣지 않는다.

실습 ③ — 맡긴다 20분

프롬프트 예시

"공공데이터포털의 국토교통부 아파트 매매 실거래가 API를 쓰려고 해. 인증키는 따로 알려줄게.

지역은 청주시 상당구(LAWD_CD 43111), 기간은 최근 12개월이야. 열두 달을 각각 받아서 CSV 한 장으로 합쳐 줘.

합치기 전에 어떻게 받아서 어떻게 합칠지 먼저 알려 줘. 다 받은 뒤에는 달마다 몇 건이 왔는지 표로 보여 줘."

마지막 두 문장이 핵심이다. 받기 전에 방법을, 받은 뒤에 건수를 요구한다 — 그래야 ①에서 센 건수와 맞춰 볼 수 있다.

건수가 다르면 멈춘다. 기간 해석이 다른지, 취소 거래를 포함했는지 물어본다.

MCP 로도 한 번 받아 본다. 3주차에 붙인 KOSIS MCP 로 자기 연구질문에 필요한 통계표를 하나 받는다. 인증키가 없어 바로 된다. 받은 뒤 통계표ID 와 기관을 되묻는 것까지가 실습이다.

② 깃허브

내 컴퓨터 밖에 두기

깃은 내 컴퓨터 안의 기록이다. 노트북이 고장 나면 함께 사라진다.

깃허브는 그 기록을 인터넷에 올려 두는 곳이다. 백업이자, 남에게 보여 주는 창구다.

터미널 · gh 를 설치하고 로그인한 뒤

공개할 것과 하지 않을 것

이 수업이라면
공개(public) 분석 스크립트 · 로직 문서 · 결과표 · README
비공개(private) 확정 전 초안, 개인정보가 섞였을 가능성이 있는 것

공개는 되돌리기 어렵다. 헷갈리면 비공개로 만들고 나중에 바꾼다 — 반대 방향은 이미 늦다.

COMPAS 비공개 데이터는 어느 쪽에도 올리지 않는다.

PR — 합치기 전에 보여 주기

풀 리퀘스트(PR)는 "이렇게 바꾸려는데 봐 주세요" 라는 요청이다. 바뀐 부분이 한눈에 보이고, 줄마다 의견을 달 수 있다.

터미널
git switch -c 면적하한-실험
# … 작업 …
git push -u origin 면적하한-실험
gh pr create

클로드에게 "브랜치 만들고 PR 까지 올려 줘" 라고 해도 된다. 올리기 전에 무엇을 담을지 확인한다.

GitHub Actions 위에서 돌기 때문에 저장소 관리자 권한과 인증 설정이 필요하다. 팀으로 일할 때 쓰는 기능이라 오늘은 개념만 본다.

주의 — 이 수업에서 실제로 겪는 사고

사고막는 법
인증키를 커밋했다 첫 커밋 전에 .gitignore 부터 만든다. 이미 올렸다면 그 키를 폐기하고 새로 발급받는다 — 기록에서 지우는 것보다 그게 빠르고 확실하다
비공개 데이터를 올렸다COMPAS 비공개분·개인정보는 저장소에 넣지 않는다. 받는 방법만 적는다
큰 파일로 저장소가 막혔다원본 데이터는 .gitignore 로 뺀다
AI 가 고친 걸 못 되돌린다작업을 시작하기 전에 커밋해 둔다. 되돌릴 지점이 있어야 마음 놓고 시킨다

첫 줄이 가장 흔하고 가장 아프다. 공개 저장소는 검색된다.

실습

내 분석을 저장소로 만들기 — 약 1시간 30분

오늘 실습의 도착점

남이 README 만 보고 내 결과를 다시 만들 수 있는 저장소

시각할 일끝났다는 신호
0:00–0:25① 기록을 시작한다첫 커밋이 남았다
0:25–0:55② 브랜치로 실험하고 되돌린다main 이 그대로다
0:55–1:30③ 서로 재현해 본다남의 결과를 내가 만들었다

시작 전 확인

  • 지난주 ds2026/ 폴더 (CLAUDE.md · 스킬 · 에이전트가 들어 있다)
  • 깃 설치 · 깃허브 계정 · gh 설치

③은 짝이 필요하다. 홀수면 셋이 한 조로 돌려 가며 한다.

① 기록을 시작한다 0:00–0:25

  1. gh auth login 으로 로그인한다 (브라우저가 열린다) 5분
  2. ds2026/ 에서 git init 1분
  3. 커밋하기 전에 .gitignore 를 만든다 8분
  4. git status 로 올라갈 목록을 눈으로 읽는다 3분
  5. git add . → git commit -m "…" 3분

3번을 이렇게 시킨다

"이 폴더를 깃 저장소로 만들려고 해. 먼저 어떤 파일이 올라가면 안 되는지 목록으로 알려 주고 .gitignore 초안을 보여 줘. 내가 확인하면 커밋하자."

✓ 확인 지점 — git status 목록에 인증키·원본 CSV 가 없다. 보이면 .gitignore 를 고치고 다시 본다.

② 실험하고 되돌린다 0:25–0:55

  1. git switch -c 면적하한-실험 2분
  2. CLAUDE.md 의 면적 하한을 85㎡ 로 바꾸고 분석을 다시 돌린다 10분
  3. git diff 로 무엇이 바뀌었는지 보고 커밋한다 5분
  4. git switch main 으로 돌아간다 2분
  5. CLAUDE.md 를 열어 본다. 분석도 다시 돌려 본다 6분
  6. 실험을 살릴지 버릴지 정하고, 버릴 거면 브랜치를 지운다 5분
✓ 확인 지점 — 5번에서 CLAUDE.md 가 60㎡ 로 돌아와 있다. 결과표도 원래 값이다. 실험이 본 작업을 건드리지 않았다.
switch 가 거부되면 — 저장하지 않은 변경이 있는 것이다. 커밋하거나 되돌린 뒤 다시 한다. 무엇을 어떻게 할지는 클로드에게 물어보고 설명을 듣고 승인한다.

③-1 올리고 설명서를 쓴다 0:55–1:15

  1. gh repo create 로 저장소를 만들고 올린다. 공개 여부를 스스로 정하고 이유를 한 줄 적는다 7분
  2. README.md 를 쓴다 10분
  3. 커밋하고 올린다. 브라우저로 저장소를 열어 눈으로 확인한다 3분

README 에 반드시 들어갈 넷

무엇을 했나한두 문장
데이터 받는 법출처 · 조건 · 인증키를 어디에 넣나 (5주차 출처 문서를 옮긴다)
분석 규칙CLAUDE.md 를 가리키고 요점만
다시 만드는 순서실행할 명령을 순서대로
✓ 확인 지점 — 브라우저에서 저장소를 열었을 때 인증키도 원본 데이터도 보이지 않는다.

③-2 서로 재현해 본다 1:15–1:30

  1. 옆 사람과 저장소 주소를 바꾼다 1분
  2. 상대 저장소를 받는다 — git clone <주소> 2분
  3. README 만 보고 상대의 결과를 다시 만들어 본다. 막히면 물어보지 말고 그 지점을 적는다 8분
  4. 막힌 지점을 상대에게 알려 준다. 받은 지적으로 자기 README 를 고친다 4분
✓ 확인 지점 — 상대의 결과표와 같은 숫자가 나온다. 안 나오면 README 에 빠진 것이 있다는 뜻이고, 그 발견이 오늘의 성과다.
시간이 모자라면 — 3번의 막힌 지점 목록까지만 하고 4번은 집에서. 일찍 끝났으면 상대 저장소에 브랜치를 만들어 README 를 고치고 PR 을 올려 본다.

제출물

무엇어느 정도면 되나
저장소 주소공개 여부와 그렇게 정한 이유 한 줄
커밋 기록git log --oneline 결과. 메시지만 읽고 흐름이 보여야 한다
README넷이 다 있고 ③-2 로 고친 흔적이 있을 것
재현 후기상대 저장소에서 어디서 막혔는지와 내 README 를 어떻게 고쳤는지

마지막 줄이 이 강의의 핵심이다. 내가 아는 것과 적어 둔 것은 다르다 — 남이 막히는 자리에서만 그 차이가 드러난다.
