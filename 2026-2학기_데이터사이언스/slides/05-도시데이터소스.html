인증키조차 필요 없는 경우도 있다

3주차에 붙인 KOSIS MCP

앞의 실거래가는 인증키를 받아 API 를 불렀다. KOSIS 통계표에는 그 단계가 없다 — 주소 하나로 붙는 MCP 서버를 시범 운영한다. 1,360여 종 국가승인통계, 26만여 통계표가 대상이다.

통계표 번호를 미리 알 필요도 없다. kosis_search 가 표를 찾고 kosis_region_code 가 청주시 = 43110 을 돌려준다. 그 둘을 kosis_get_data 에 넣으면 숫자가 온다.

다만 시범서비스이며 국가데이터처의 공식 입장이 아니다. 중요한 판단 전에는 KOSIS 원자료를 확인한다 (KOSIS 공지, 2026-07-08). 뒤에서 이 서버로 청주시 인구를 받아 본다.

맡겼으면 확인한다

①②③ 이 같은 182건을 내놓아야 한다. 어긋나면 거기서 멈춘다

무엇을 보나왜어긋나면
건수①에서 화면으로 센 182건이 기준이다 기간을 어떻게 읽었는지, 취소 거래를 넣었는지 묻는다
어디서 왔나API 이름과 제공기관을 되묻는다 대지 못하면 그 숫자는 쓰지 않는다
자릿수가 그럴듯한가상당구 한 달에 182건이면 하루 여섯 건꼴이다 자릿수가 어긋나면 합산을 잘못한 것이다
자릿수 확인은 실제로 쓰인다. 뒤에 나오는 청주시 인구에서 처음 합산이 167만으로 나왔다. 받아 온 표에 「계」 행과 연령별 행이 함께 있었고 그것을 모르고 다 더한 것이다. 청주시가 85만 규모라는 것만 알아도 걸린다.

①②를 해 본 사람만 ③을 의심할 수 있다. 세 번 받아 보는 이유가 이것이다.

직접 받기 — 청주시 인구 (2000~2024)

질문은 하나다 — 청주시 인구는 25년 동안 어떻게 변했나?

  1. kosis.kr → 국내통계 → 주제별 통계
  2. 인구 → 주민등록인구현황 → 행정구역(시군구)별, 성별 인구수
  3. 표가 열리면 조회설정에서 셋을 고른다 — 행정구역 충청북도 > 청주시 · 항목 총인구수 · 시점 2000 ~ 2024 (년)
  4. 다운로드 → CSV 또는 EXCEL

KOSIS MCP 를 붙인다 — 모든 프로젝트에서 쓰게

3주차에는 한 프로젝트에 붙였다
이번에는 전역(user)으로 붙인다

클로드가 실행하는 명령
claude mcp add --transport http \
  kosis https://kosismcp2026.vercel.app/api/mcp \

# 범위
--scope local     나 · 이 프로젝트에서만 (기본값)
--scope project   .mcp.json 으로 저장소에 함께
--scope user      내 모든 프로젝트

인증키가 없는 원격 서버라 리모트 컨트롤로 시켜도 된다

세션을 열고 이렇게 시킨다

"https://kosismcp2026.vercel.app/api/mcp — 이 KOSIS 원격 MCP 를 내 모든 프로젝트에서 쓸 수 있게 user 범위(전역)로 붙여 줘. 인증키는 없어.

붙인 뒤에 /mcp 로 연결을 확인하고, 청주시 총인구 2024년 값을 하나 받아서 실제로 숫자가 오는지 보여 줘."

✓ 확인 지점 — 새 세션을 열어 /mcp 에 kosis 가 연결됨으로 뜬다. 다른 폴더에서 열어도 뜨면 전역으로 붙은 것이다. 숫자는 다음 장의 2024년 값과 같아야 한다.

AI 에 맡기기 — 청주시 인구 (2000~2024)

이렇게 묻는다

"청주시 총인구를 2000년부터 2024년까지 연도별로 받아 줘. 어느 통계표에서 왔는지도 같이 알려 줘."

클로드가 한 일 — 다섯 번 불렀다

  1. kosis_local_search 로 표를 찾음 → DT_1B04006, 그런데 2008년부터다
  2. kosis_search 로 다시 찾음 → DT_1B040A3, 1992년부터 ✓
  3. kosis_region_code 로 청주시 = 43110
  4. kosis_get_data — 실패 항목ID 를 T2 로 넣었다. 유효값은 T20·T21·T22 였다
  5. kosis_get_data — 25줄이 왔다

표를 잘못 짚는 것은 어느 쪽에서나 같다 — 맡기면 2번에서 걸러진다.

실습 — 오늘 만들 것

대상

청주시 상당구 아파트 매매 실거래가 · 최근 12개월

왜 세 번이나 받나

  • 같은 데이터가 나와야 내가 제대로 받았는지 알 수 있다
  • 세 방식의 손이 가는 정도를 몸으로 비교하게 된다
  • ③ 이 편하다는 것을 알되, ①②를 해 봐야 ③의 결과를 의심할 수 있다

실습 ① — 손으로 받는다 20분

  1. 국토교통부 실거래가 공개시스템 rt.molit.go.kr 에 들어간다
  2. 아파트 → 매매 → 지역을 충청북도 청주시 상당구로, 기간을 최근 12개월로 지정한다
  3. 화면에서 결과를 훑어본다 — 몇 건인가
  4. CSV 로 내려받아 열어 본다. 열 이름과 단위를 확인한다

메모해 둘 것: 전체 건수. ②③의 결과를 이것과 맞춰 본다.

조건을 하나씩 바꿔 보면 무엇이 어떻게 걸러지는지 보인다. API 의 파라미터가 곧 이 화면이다.

실습 ② — 인증키를 받는다 35분

  1. data.go.kr 회원가입 (공공데이터포털)
  2. "국토교통부_아파트 매매 실거래가 자료" 를 찾아 활용신청한다. 자동 승인이라 곧 쓸 수 있다
  3. 마이페이지에서 인증키(serviceKey)를 확인한다. 상세 화면에 요청 주소와 파라미터 설명이 함께 있다
  4. code.go.kr/stdcode/regCodeL.do 에서 법정동코드를 찾는다 — 청주시 상당구 4311100000 → 앞 5자리 43111
  5. 서원구·흥덕구·청원구의 코드도 직접 찾아 적어 둔다

인증키는 남에게 보이지 않는다. 화면 공유나 제출물에 그대로 넣지 않는다.

실습 ③ — 맡긴다 20분

프롬프트 예시

"공공데이터포털의 국토교통부 아파트 매매 실거래가 API를 쓰려고 해. 인증키는 따로 알려줄게.

지역은 청주시 상당구(LAWD_CD 43111), 기간은 최근 12개월이야. 열두 달을 각각 받아서 CSV 한 장으로 합쳐 줘.

합치기 전에 어떻게 받아서 어떻게 합칠지 먼저 알려 줘. 다 받은 뒤에는 달마다 몇 건이 왔는지 표로 보여 줘."

마지막 두 문장이 핵심이다. 받기 전에 방법을, 받은 뒤에 건수를 요구한다 — 그래야 ①에서 센 건수와 맞춰 볼 수 있다.

건수가 다르면 멈춘다. 기간 해석이 다른지, 취소 거래를 포함했는지 물어본다.

MCP 로도 한 번 받아 본다. 3주차에 붙인 KOSIS MCP 로 자기 연구질문에 필요한 통계표를 하나 받는다. 인증키가 없어 바로 된다. 받은 뒤 통계표ID 와 기관을 되묻는 것까지가 실습이다.

③ 클로드 + 깃

깃 관리는 모두 클로드에게 맡기기

위 명령은 알고만 있는다. 실제로는 모두 클로드에게 요청하거나, 클로드의 판단을 확인하는 형태로 진행한다

이렇게 시킨다 — 한 마디면 된다

"커밋해 줘."

"깃허브에 올려 줘."

"어제 커밋한 상태로 되돌려 줘."

"이 저장소의 커밋 기록을 읽고
분석이 어떻게 바뀌어 왔는지 정리해 줘."

무엇을 담을지, 메시지를 어떻게 쓸지는 클로드가 바뀐 내용을 보고 정한다

클로드가 먼저 확인을 청할 때 (예)

"올라갈 목록에 .env 가 있습니다. 인증키가 든 파일 같습니다.
.gitignore 에 넣고 빼고 커밋할까요?"

"이렇게 되돌리면 아직 커밋하지 않은 변경 3개 파일이 사라집니다.
진행할까요?"

이때가 내가 판단하는 자리다 — 무엇이 지워지고 무엇이 올라가는지 읽고 승인한다

커밋 전에 무엇이 담기는지 한 번 본다 — 모르고 승인하면 인증키가 함께 간다.

깃 사용시 주의사항

사고막는 법
인증키를 커밋했다 첫 커밋 전에 .gitignore 부터 만든다. 이미 올렸다면 그 키를 폐기하고 새로 발급받는다 — 기록에서 지우는 것보다 그게 빠르고 확실하다
비공개 데이터를 올렸다COMPAS 비공개분·개인정보는 저장소에 넣지 않는다. 받는 방법만 적는다
큰 파일로 저장소가 막혔다원본 데이터는 .gitignore 로 뺀다
AI 가 고친 걸 못 되돌린다작업을 시작하기 전에 커밋해 둔다. 되돌릴 지점이 있어야 마음 놓고 시킨다

첫 줄이 가장 흔하고 가장 아프다. 공개 저장소는 검색된다.

앞으로의 프로젝트는 깃으로 관리한다

이 수업의 모든 프로젝트는 깃으로 기록하고 깃허브에 올린다
습관으로 만든다

→ 시작할 때 "커밋해 줘" · 끝날 때 "커밋하고 깃허브에 올려 줘" · 다른 컴퓨터에서는 "깃허브에서 받아 와 줘"

실습

2주차부터 쌓은 내 위키를 깃허브에 올리기 — 약 1시간 30분

오늘 실습의 도착점

2주차부터 쌓은 내 위키가 깃허브 비공개 저장소에 올라가 있고, 브라우저에서 눈으로 확인된다

시각할 일끝났다는 신호
0:00–0:20⓪ 깃 설치 · 깃허브 가입git --version 이 찍히고 gh auth status 가 로그인을 보인다
0:20–0:45① 기록을 시작한다첫 커밋에 raw/ 와 인증키가 없다
0:45–1:05② 깃허브에 올린다저장소 주소가 나왔다
1:05–1:30③ 깃허브에서 확인한다브라우저에 wiki/ 가 보이고 raw/ 는 없다

시작 전 확인

  • my-wiki/ — 이미 프로젝트 폴더이고 리모트 컨트롤로 이어져 있다
  • 명령은 화면에서 읽고 확인만 한다. 실행은 클로드에게 시킨다

⓪-1 깃 설치 — 클로드에게 맡긴다

원격으로 돌릴 때가 많다. 설치는 내 손이 아니라 세션이 도는 PC 에서 일어난다

이렇게 시킨다

"이 컴퓨터에 git 과 gh(깃허브 CLI) 가 설치돼 있는지 확인해 줘. 없으면 이 운영체제에 맞는 방법으로 설치하되, 설치 명령을 실행하기 전에 무엇을 하는지 먼저 알려 줘. 끝나면 두 프로그램의 버전을 보여 줘."

✓ 확인 지점 — 버전 두 줄이 찍힌다
git version 2.… · gh version …
클로드가 실행하는 명령 — 운영체제마다 다르다
# 맥 (Homebrew 가 있을 때)
brew install git gh

# 윈도우
winget install --id Git.Git -e --source winget
winget install --id GitHub.cli --source winget
PC 화면에 확인 창이 뜨는 경우 — 맥의 xcode-select --install 이나 윈도우의 관리자 권한 창은 PC 앞에서 눌러야 한다. 원격으로는 누를 수 없으니 수업 전에 PC 에서 한 번 해 둔다. 막히면 오류 메시지를 그대로 클로드에게 준다.

출처: 깃 공식 사이트 git-scm.com/install · 깃허브 CLI cli.github.com (2026. 10. 12. 확인)

⓪-2 깃허브 가입 — 내가 직접 한다

계정은 내가 만든다
내 이메일과 비밀번호라 클로드에게 시키지 않는다

  1. github.com → Sign up
  2. 이메일 · 비밀번호 · 사용자 이름을 정한다
    사용자 이름이 저장소 주소가 된다 — github.com/사용자이름
  3. 이메일로 온 인증 코드를 넣는다
  4. Free 로 시작한다

그다음, 클로드와 깃허브를 연동한다

이렇게 시킨다

"이 컴퓨터의 클로드가 내 깃허브 계정으로 일할 수 있게 연동해 줘. 앞으로 내가 "깃허브에 올려 줘", "깃허브에서 받아 와 줘" 라고만 해도 push 와 pull 이 바로 되도록 설정해 줘.

로그인할 때 일회용 코드가 나오면 바로 보여 주고, 끝나면 연동이 됐는지 확인해서 알려 줘."

클로드가 실행하는 명령 — gh auth login --web · gh auth setup-git

코드가 나오면 휴대폰이나 브라우저로 github.com/login/device 에 들어가
코드를 넣고 승인한다. 원격이어도 된다.

✓ 확인 지점 — gh auth status 에 Logged in to github.com 이 뜬다

출처: 깃허브 CLI 매뉴얼 cli.github.com/manual/gh_auth_login (2026. 10. 12. 확인)

① 기록을 시작한다 0:20–0:45

올리지 않을 것부터 정한다 — 비공개인 것은 .gitignore 로

.gitignore
raw/      # 원자료 — 강의노트·논문 원문, 저작권 자료
.env      # 인증키

나머지 — wiki/ · CLAUDE.md · .claude/ 의 스킬과 에이전트 — 는 올린다

클로드가 실행하는 명령 — 알고만 있는다
git init
git status
git add .
git commit -m "위키 첫 기록"

이렇게 시킨다

"이 위키 폴더를 깃 저장소로 만들어 줘. raw/ 와 인증키가 든 파일(.env 같은 것)은 .gitignore 로 빼고, 나머지는 올리게 해 줘. 커밋하기 전에 올라갈 파일 목록을 보여 줘."

✓ 확인 지점 — 보여 준 목록에 raw/ 도 .env 도 없다. 보이면 .gitignore 를 고치게 하고 목록을 다시 본다.
raw/ 를 빼는 이유 — 강의노트·논문 원문은 저작권 자료다 (2주차). 비공개 저장소라도 올리지 않는다. 받는 법은 wiki/ 의 출처에 이미 적혀 있다.

② 깃허브에 올린다 0:45–1:05

이렇게 시킨다

"깃허브에 my-wiki 라는 비공개 저장소를 만들고 지금 커밋을 올려 줘. README.md 가 없으면 이 위키가 무엇인지 세 줄로 써서 함께 올려 줘. 올리기 전에 저장소 이름과 공개 여부를 한 번 확인해 줘."

✓ 확인 지점 — 올리기가 끝났다는 메시지와 함께 github.com/사용자이름/my-wiki 주소가 나온다
클로드가 실행하는 명령 — 알고만 있는다
gh repo create my-wiki --private \
  --source=. --push

비공개(private)로 둔다.
위키 페이지도 강의노트에서 나온 내용이라 저작권이 걸린다

공개로 바꾸는 것은 나중에도 된다. 반대 방향은 이미 늦다 (34쪽)

출처: 깃허브 CLI 매뉴얼 cli.github.com/manual/gh_repo_create

③ 깃허브에서 확인한다 1:05–1:30

클로드가 "올렸다" 고 해도 내 눈으로 본다 — 휴대폰 브라우저로도 된다

  1. github.com 에 로그인 → 오른쪽 위 프로필 → Your repositories
  2. my-wiki 를 연다. 이름 옆에 Private 표시가 있는지 본다
  3. 파일 목록을 본다 — wiki/ · CLAUDE.md · README.md 는 있고, raw/ · .env 는 없다
  4. wiki/ 에서 페이지 하나를 열어 본다. 출처가 붙은 그대로 보인다
  5. Commits 를 눌러 내 커밋 메시지가 남았는지 본다
✓ 확인 지점 — 3번에서 raw/ 나 .env 가 보이면 바로 클로드에게 알린다. 인증키가 올라갔으면 그 키를 폐기하고 새로 발급받는다 (깃 사용시 주의사항).

다음 주부터 위키를 갱신할 때마다 "커밋하고 깃허브에 올려 줘" 한 마디를 붙인다.

과제 — SGIS 스킬을 만들어 온다

3주차 과제는 내 일을 다뤘다. 이번엔 바깥 데이터다

SGIS(통계지리정보서비스)는 오픈API 93종을 연다 — 인구·가구·주택·사업체 통계, 행정구역 경계, 지오코딩, 격자, 자연재해.

감쌀 것은 두세 개면 된다

  1. 인증키를 오늘 신청한다 사용기간을 학기 끝까지 덮게
    https://sgis.mods.go.kr/developer/html/main.html
  2. 자기 연구질문에 필요한 API 를 두세 개 고른다
  3. 클로드에게 스킬을 만들게 한다
  4. 실제로 받아 보고 자릿수가 그럴듯한지 본다

출처: 통계지리정보서비스 개발지원센터 sgis.mods.go.kr/developer/html/main.html (2026. 9. 6. 확인). API 93종 · 인증키당 하루 50,000회

보는 것 넷 — 분량은 세지 않는다

  1. 스스로 꺼내지는가 description 이 「언제 쓰는지」를 말하는가
  2. 인증키가 어느 파일에도 없는가 이 폴더는 깃허브에 올라간다. 여기서 새면 키가 공개된다
  3. 출처가 붙어 있는가 API 이름 · 기관 · 조회 날짜
  4. 토큰 4시간을 사람이 안 만지는가
