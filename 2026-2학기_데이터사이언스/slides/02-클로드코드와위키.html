남의 컴퓨터SSH · 클라우드 세션을 화면에서 고름 ssh 로 붙어 거기서 실행
좋은 점터미널을 몰라도 됨 · 승인 화면이 읽기 쉬움 다른 명령과 이어 붙임 · 예약·반복 실행
아쉬운 점사람이 쳐야 함 — 다른 프로그램이 대신 못 부름 검은 화면이 낯섦
이 수업은 터미널을 기준으로 한다. 터미널에서 /desktop 을 치면 그 세션을 데스크탑 앱에서 이어 볼 수 있다.

원격은 양쪽 다 된다 — 앱도 SSH·클라우드로 남의 컴퓨터에서 돌린다. 갈리는 것은 「매일 아침 7시에 사람 없이 한 번 돌기」 같은 일이다. 앱은 사람이 보고 누르는 창이라 그 자리가 없다

CLAUDE.md

매 세션 시작에 자동으로 읽히는 규칙 파일

어디에 두느냐로 범위가 갈린다
~/.claude/CLAUDE.md
   전역 — 어느 폴더에서 열어도 읽힘

./CLAUDE.md
   이 폴더 — 남과 공유할 수 있음
   가장 많이 쓰는 자리

./CLAUDE.local.md
   나만 — 공유하지 않음

셋이 다 있으면 아래쪽이 이긴다 — 구체적인 것이 덮는다

만들고 고치는 법

  • /init — 폴더를 훑어 초안을 만들어 줌
  • /memory — 지금 읽히는 파일을 열어 고침

무엇을 적나

  • 이 폴더가 무엇을 하는 곳인지 한두 줄
  • 폴더 규칙 — 어디를 고쳐도 되고 어디는 안 되나
  • 금지 사항
  • 자주 시키는 절차
말로 한 규칙은 다음 대화에서 사라진다. 파일에 적으면 매번 읽고 시작한다.

컨텍스트

클로드가 지금 들고 있는 것 — 대화 · 읽은 파일 · CLAUDE.md 전부

한 번에 들고 있을 수 있는 양에 한도가 있다. 넘으면 오래된 것부터 요약으로 접힌다

이런 증상이면이렇게 한다
대화가 길어졌다/compact 로 접는다
답이 엉뚱해지기 시작했다 /compact 위키 규칙 중심으로 — 방향을 붙인다
아예 다른 일로 넘어간다/clear 로 비운다
얼마나 찼는지 모르겠다/context 로 본다

파일을 많이 읽힐수록 빨리 찬다. 폴더를 통째로 읽히지 말고 필요한 것만 @ 로 가리킨다

세션

클로드를 켠 순간부터 끄는 순간까지가 한 세션

세션이 끝나면 대화는 사라지고 파일은 남는다. 규칙을 CLAUDE.md 에 적어 두는 이유가 이것이다

이어 쓰기

claude --continue 직전 것을 이어서
claude --resume골라서 이어서
/rename이름을 붙여 둠

새로 여는 게 나을 때

  • 아예 다른 일로 넘어갈 때
  • 같은 오류가 계속 반복될 때
  • 컨텍스트가 다 찼을 때
터미널 창을 여러 개 열면 세션도 여러 개다. 같은 파일을 두 세션이 동시에 고치지 않게 맡은 자리를 나눈다.

지시가 좁을수록 결과가 좁아진다

  1. 무엇을 어디서 "고쳐 줘" 가 아니라 "07-기술적분석.md 의 표 두 번째 줄을 고쳐 줘"
  2. 한 번에 하나 세 가지를 한 문장에 담으면 하나만 제대로 된다
  3. 결과물의 형태를 정함 "표로" · "마크다운 파일 하나로" · "목록만"
  4. @ 로 파일을 가리킴 @강의노트.pdf · @raw/lectures/ 처럼 폴더도 됨

흐린 지시 → 좁힌 지시

"강의노트 정리해 줘"

→ "@raw/lectures/도시경제학/ 의 PDF 를 읽고 개념마다 한 장씩 wiki/topics/ 에 만들어 줘. 만들 목록을 먼저 보여 줘."

잘못 고쳤을 때 · 에러가 났을 때

되감기

  • 입력창이 빈 상태에서 Esc 두 번, 또는 /rewind
  • 시점을 골라 그때로 되돌림
  • 클로드가 편집 도구로 고친 것만 되돌아감
  • 터미널 명령으로 지운 파일은 되돌아오지 않음

작업이 이상한 방향으로 달리기 시작하면 Ctrl+C 로 먼저 멈춘다

에러

  1. 화면을 그대로 준다 복사해 붙이거나 Ctrl+V 로 캡처를 붙임
  2. 세 가지를 적는다 언제부터 · 무엇을 하면 · 어떤 증상
  3. 같은 에러가 반복되면 CLAUDE.md 에 적고 새 세션으로 다시 시작
"전체 다 고쳐 줘" 는 범위를 넓혀 더 망가뜨린다. 한 파일 · 한 증상으로 좁힌다.

하지 말 것 셋

  • 인증키 · 비밀번호를 대화창에 붙여 넣지 않는다 — 대화 기록과 로그에 남는다. 5주차에 받는 API 키가 이 경우다
  • 권한을 통째로 건너뛰지 않는다 — --dangerously-skip-permissions 는 확인 없이 지우고 실행한다
  • 되돌릴 수 없는 폴더에서 시작하지 않는다 — 위키는 my-wiki/ 안에서만 돌린다

사고는 대개 "귀찮아서 다 허용" 에서 난다

5주차에 깃을 배우면 되돌리는 폭이 넓어진다. 그전까지는 폴더를 통째로 복사해 두는 것이 유일한 백업이다.

지식 위키

무엇을 왜 쌓는가

매번 다시 읽는가, 쌓아 두는가

파일을 올려 묻기 위키로 쌓기
질문할 때마다처음부터 다시 읽음이미 정리된 것을 읽음
과목 간 연결물을 때만 잠깐페이지에 남음
지난 학기 것다시 올려야 함그대로 있음
남는 것대화 기록내 폴더의 마크다운 파일

쌓이는 쪽이 학기가 갈수록 유리해진다

여기서 나는 모으고 묻고 판정한다. 페이지는 클로드가 쓴다

위키의 구조

my-wiki/
raw/         모은 것 — 클로드가 고치지 않는다
  lectures/  강의노트 (과목별)
  papers/    논문
  talks/     콜로퀴움 · 세미나 발표자료
  books/     전공서적 — 서지와 읽은 장의 메모
notes/       내가 쓴 것 — 필기 · 메모 · 아이디어
wiki/        클로드가 쓰는 것
  topics/    개념과 방법론 — 집적경제 · 회귀분석
  sources/   읽은 자료 한 건 = 한 장
  index.md   전체 목록   log.md    언제 무엇을 넣었나
questions/   강의가 말해 주지 않은 것을 논의한 기록
CLAUDE.md    규칙 — 오늘 내가 쓴다

읽기 전용은 raw · notes, 클로드가 쓰는 곳은 wiki · questions

폴더를 나누는 이유 — 근거의 층위

어디서 온 말이냐에 따라 무게가 다르다

갈래무엇인가 어떻게 다루나
raw/papers논문 — 동료심사를 거친 것 가장 무겁게. 주장의 근거로 쓸 수 있음
raw/lectures강의노트 — 교수가 정리해 준 것 시험 범위의 기준. 개념 페이지의 뼈대
raw/talks · books심사 없는 발표 · 저술 맥락과 사례로. 논문과 어긋나면 어긋난다고 적음
notes내가 쓴 것 클로드는 읽고 인용만. 고치지 않음

남의 말과 내 생각이 한 페이지에서 섞이면 나중에 갈라낼 수 없다

페이지 두 종류, 규칙 셋

페이지

  • topics/ 개념과 방법론 — 집적경제, 회귀분석
  • sources/ 읽은 자료 한 건 — 강의 · 논문 · 발표 · 책

개념과 방법론을 폴더로 가르지 않음 — 회귀분석이 어느 쪽인지 고민할 시간을 아낌. 구분은 type: 한 줄

frontmatter — 네 줄
type: concept
title: "집적경제 (agglomeration economies)"
sources: ["도시경제학 3강"]
status: draft

규칙

  1. 출처를 문장 옆에 — (도시경제학 3강 p.12)
  2. 배운 것과 찾은 것을 절로 분리 — 뒤 절에 「확인 필요」
  3. 다른 페이지로 잇기 — 이을 곳 없으면 만들지 않음
규칙 ①이 하는 일. 노트에 없는 문장에는 출처가 없다. 규칙만 지키면 지어낸 문장이 저절로 드러난다.

위키의 CLAUDE.md 는 이렇게 생겼다

11쪽에서 본 ./CLAUDE.md 자리다. 위키 규칙 다섯 줄이 들어간다

CLAUDE.md
# 내 지식 위키

raw/ 와 notes/ 는 읽기 전용이다. 고치지 않는다.
사실 문장 옆에 출처를 적는다.
노트에 없는 것은 절을 갈라 「확인 필요」를 단다.
새 페이지를 만들기 전에 wiki/index.md 를 먼저 읽는다.
인제스트가 끝나면 index.md 와 log.md 를 갱신한다.

오늘 실습 ③에서 이 파일을 자기 손으로 고친다 — 마음에 안 드는 결과가 곧 규칙이 된다

강의노트만이 아니다

같은 폴더에 이런 것도 들어간다

  • 논문 — 세미나에서 읽은 것, 졸업논문 준비 자료
  • 콜로퀴움 발표자료 — 학과 초청 강연, 학회 발표
  • 전공서적 — 읽은 장의 요약과 서지
  • 내 아이디어 — notes/ 에 날짜를 붙여 남긴다

넣는 방법은 종류를 가리지 않고 같다 — raw/ 에 놓고 인제스트를 시킨다

같은 개념이 강의·논문·발표에서 한 페이지에 쌓이는 것이 이 위키의 값어치

오늘 실습은 한두 개까지. 책을 통째로 넣을지 요약만 넣을지는 각자 정한다. 저작권이 있는 자료이므로 위키는 비공개로 둔다.

실습

내 지식 위키 만들기 — 약 1시간 20분

① 설치 확인 0:00–0:10

  1. 터미널을 연다 (맥 터미널 · 윈도우 PowerShell)
  2. 위키 폴더를 만든다 — mkdir my-wiki && cd my-wiki
  3. claude 를 실행하고 로그인한다
  4. "이 폴더에 뭐가 있어?" 라고 물어본다
되었는지 확인. 클로드가 빈 폴더라고 답한다.
막히면. 사전 과제에서 캡처해 온 오류 화면을 지금 함께 본다. 혼자 붙들고 있지 않는다 — 옆 사람과 화면을 맞춰 본다.

② 카파시의 글을 읽는다 0:10–0:30

위키의 틀은 오늘 내가 주지 않는다. 원문에서 각자 뽑아낸다

읽을 것 — 안드레이 카파시 Andrej Karpathy, llm-wiki.md (2026)
gist.github.com/karpathy/442a6bf555914893e9891c11519de94f
  1. 주소를 클로드에게 주고 한국어로 옮기게 한다
  2. 번역에서 멈추지 않는다 — 특징 다섯 개를 뽑고 근거 문장을 달게 한다
  3. 그 결과를 notes/카파시-위키-정리.md 로 저장한다

프롬프트

"이 글을 한국어로 옮겨 줘. 그다음 파일을 올려 묻는 방식과 무엇이 다른지 특징을 다섯 개로 뽑고, 각각 원문의 어느 문장에서 나왔는지 달아 줘."

되었는지 확인. 「위키는 LLM 이 쓰고 사람은 고르고 묻는다」 「원자료는 고치지 않는다」 「규칙 파일이 따로 있다」 같은 것이 잡히면 됐다.

③ 내 위키를 만들게 한다 0:30–1:00

카파시는 폴더 이름도 페이지 형식도 정해 주지 않는다. 그 자리를 내가 정한다

  1. 앞에서 만든 notes/카파시-위키-정리.md 를 준다
  2. 내가 넣을 자료가 무엇인지 말한다 강의노트 · 논문 · 세미나 발표자료 · 전공서적
  3. 안을 먼저 받고 고른다 바로 만들게 하지 않는다 — 계획 모드를 써도 좋다
  4. 고른 구조로 폴더와 CLAUDE.md 를 만들게 한다
  5. 자료 하나를 실제로 넣어 본다

프롬프트

"@notes/카파시-위키-정리.md 를 읽어 줘. 나는 강의노트 · 논문 · 세미나 발표자료를 넣을 거야. 이 방식대로 폴더 구조와 CLAUDE.md 를 만들려고 해. 먼저 안을 두세 개 제안해 줘. 내가 고른 다음에 만들자."

되었는지 확인. 원자료 자리와 클로드가 쓰는 자리가 갈려 있고, CLAUDE.md 에 내 말로 쓴 규칙이 들어가 있다.

  1. 둘을 훑고 내 위키에 없는 것 두 개를 고른다
  2. 왜 필요한지 한 줄로 적는다
  3. CLAUDE.md 를 고치고 같은 자료를 다시 넣어 본다

베끼지 않는다. 고른 이유를 말할 수 있는 것만 가져온다

남의 위키는 그 사람의 자료와 일에 맞춰진 것이다. 그대로 옮기면 쓰지 않는 폴더만 늘어난다

제출물

  • notes/카파시-위키-정리.md — 특징 다섯과 근거 문장
  • 내가 정한 폴더 구조 — 왜 그렇게 갈랐는지 두세 줄
  • CLAUDE.md — 내 말로 쓴 규칙
  • wiki/ 페이지 세 장 · index.md · log.md
  • 남의 위키에서 가져온 것 두 개와 그 이유

페이지 수는 세지 않는다. 고른 근거를 말할 수 있는지를 본다

폴더를 통째로 압축해 제출한다. 구조가 서로 달라도 된다 — 같은 글에서 서로 다른 위키가 나오는 것이 정상이다. 5주차에 깃허브 비공개 저장소로 옮긴다.
